# Catalogue
Authored document owning the parent repository's curation criteria.
## Membership
User-stated criterion: a project qualifies through creativity OR current or credible expected usefulness without merely repeating an existing open-source project OR substantial work proving it is trying.
Approved interpretation: meaningful differentiation can qualify a useful project despite existing alternatives; substantial work requires meaningful implementation or experimental evidence relative to scope, not file/commit counts, a large codebase or mandatory test-suite presence.
Membership and prominence are separate decisions; qualifying for retention does not automatically justify featuring a project.
## Assessment
The user approved the nine-judgement representation and one M1 delivery gate in ../plan/catalogue-redesign.md. This authorizes rubric/schema work and a complete full-collection assessment through that gate; it is not authority to remove anything, modify children, run model experiments or change the parent root README.
Use project cards linked to contribution cards for consequential independently reusable practices or insights, relevant internal modules and outputs. Assess non-obviousness, depth of thought, transferability, current and conditional-future product value, current and conditional-future contribution value, technical feasibility and delivery feasibility separately; ../method/catalogue.md owns aspect anchors, evidence conventions, schema and handoff checks. Do not create a total or artificial tie-break.
The seven insight/value judgements are justified integer 0–10 estimates with plausible bounds or unknown. Feasibility is a justified subjective probability range only when constraints and horizon are explicit; otherwise unknown. Conditional-future value is conditional on completing the stated scope and does not include delivery probability. Human/AI effort is descriptive with provenance or unknown, never inferred from Git. Maturity, evidence strength, audience, tags, delivery form, requirements and reuse/extraction burden stay separate from value.
Creativity considers both novelty and interestingness; bounded public research can establish overlap, not global originality or equivalence of implementations.
Each project needs a short description, distinctive contribution, evidence, membership reason and next decisive step; runtime verification, source inspection and forecast remain distinguishable. Project inside value references contribution sources instead of duplicating their ratings. Existing draft assessments may remain disputed until WP3 imports the complete replacement.

## Boundaries
The assessment mandate covers investigation and recommendations, not implied cleanup or implementation fixes. The separately authorized issue-recording and named removal actions are scoped in ../plan/catalogue-curation.md; private information, pre-existing work, remote repositories and published history remain protected. Parent README generation and broad project repair are not included.
Removal requires a separately approved operation preserving unique work, local modifications, unpushed commits and valuable untracked files.
The README presentation remains provisional: an authored front door and generated showcase linking to an evidence-backed full catalogue.
