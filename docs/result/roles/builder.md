## The seat nobody writes for

The builder receives 90 lines of Node guide and 19 lines of Build guide. The Node guide's first sentence is "You own a roadmap and you do not execute the work you split off." The builder executes. Its thirteen sections are, in order: before the person speaks, the word, the first contract, the contract, launch, while it runs, when something comes back, when the person is needed, when a milestone is reached, the loop that ends, as a container, when the session ends, when it goes wrong.

Read that list as a builder and notice that every one of them is an act of *issuing*: writing a contract, launching a package, waiting on children, triaging what comes back, stopping at a milestone. Not one section is written for the node on the other end of the launch — the one that receives the contract, does the work, and hands it back. The Build guide's nineteen lines describe *what* to build and say nothing about *where the builder stands while building it*: no directory, no inbox, no area, no return, no commit.

So the builder's document set is thin exactly where the builder stands. That is not a characterisation; it is checkable, and it is the single cause of thirteen of the sixteen authority gaps below — the moments where the builder is the recipient of something the Node guide only describes being sent: rows 1, 2, 3, 5, 8, 18, 19, 21, 22, 23, 24, 25, 27.

Two sentences make the mismatch sharpest. Line 271 tells the builder it does not execute what it splits. Line 3 tells it what it is for: "Builds one behaviour-complete slice with its check." The builder is rendered with a guide whose first sentence denies the purpose in its own frontmatter. I checked role descriptions only and read no other guide, so I claim this of the builder and not as a comparison with its siblings.

## How I scored

Per `docs/method/review.md`. `stated` — a settling sentence exists and the result can be checked after the fact. `delegated` — the documents say the choice is mine and bound it. `ambiguous` — two readings, different actions. `silent` — nothing addresses it.

I marked each row **authority** or **procedure**. Authority means the question is *who decides*. Those rows may not be `ambiguous` or `silent`; a node that has to infer authority will infer in its own favour. Procedure rows may be `delegated`, but an implicit delegation scores as `silent`, because freedom nobody granted is freedom nobody can review.

Absences are claimed with the command and its hit count, so the next node re-runs it rather than believing me. All counts are over `agent-policy/agents/builder.md`:

## Effort

**What was tried.** I walked a session in the order the Node guide's own sequence imposes, then the order the Build guide imposes, and for each moment where a builder must choose, searched the complete document set for a sentence that settles it. Twenty-seven moments survived that pass; the ones that came back `stated` are rows 10 and 17, which is the evidence that the search worked rather than that the set is empty everywhere.

**Why each path is closed.** The search space is complete, not sampled: `agents/builder.md` is a render of six files and carries nothing else, so a sentence absent from it is absent for this role. Each absence above names its command and its hit count, so the next node re-runs the search instead of trusting the count.

**What would reopen one.** Three things, and I can name all three:

1. A project entrance document. Line 104 says the entrance answers "where a thing is when that differs from the general convention". That is exactly what rows 1, 2 and 26 need — but it is the document a node writes about a directory it already has, and a builder that has never run has none.
2. A contract that carries paths, area, degree and the checks by name. If the dispatching node writes those into the orientation, rows 1, 21, 23 and 26 collapse without a word changing in the law. On the evidence of 296 ("This is what stops the child from exploring, and it costs a few hundred tokens against the thousands it saves"), the law already intends the orientation to carry exactly this, and never says so.
3. The role split. `roles.yaml` describes `builder` as "Builds one behaviour-complete slice with its check" and `worker` as "Executes exactly one work package from a contract, and reports once", with different guides. I read the descriptions and did not read the other guide. If the cases above are meant to be met by the other role, this report measures the wrong document set, and that is the first thing to check before acting on it.

**Cost.** The law is at 4768 words against a ceiling of 4768 (`law/ceiling`; `python3 agent-policy/tools/law.py --check` → "ok: 7 views, 4768 words, 26258 chars"). No row above can be closed by adding a sentence. Every one costs a deletion, and the only material visibly available to delete is the issuer-side procedure the builder never uses.

**Options, with their cost. No recommendation is attached**, because I cannot know this project's degree and 71 says an opinion about taste anchors the answer it was meant to leave open.

- **A. A recipient-side section, replacing issuer-side lines.** State once, in the shared law, what a dispatched package is: its directory and three paths, its area, the return, the commit. Cost: roughly 120 words, so roughly 120 deleted, and the candidates are the container and launch material a builder never reaches.
- **B. Four globals in the shared law.** Directory, inbox path, outbox path, document name. Closes rows 1, 2 and 26 for every role at once. Cost: four sentences against a met ceiling; deletes whatever they land on.
- **C. Accept the gap as delegation by omission.** Costs nothing to write, and nothing to review until the first wrong inference. `docs/method/review.md` refuses it in one line: an implicit delegation scores as `silent`, and authority a node infers it will infer in its own favour.

## Limits

- I read no project directory and no other role's guide. That independence is what makes the report worth having, and it is also its blind spot: I cannot say whether a project's entrance document would answer rows 1, 2 and 26, and I cannot say whether the `worker` role is the one that should have met these cases.
- Row 1's defect is partly a property of how a package is launched. A package handed explicit paths does not need them in the law. A package that wakes and must *find* its inbox does — and 112-114 promises exactly that case, so the gap is in the document and not only in the harness.
- I did not judge style and I repaired nothing. Verdicts are on whether the documents say what to do, not on whether the English is good.
- Evidence is bound to `85f0cf8`. Every count above is a search any reader can repeat; none of them is a value the document owns.
