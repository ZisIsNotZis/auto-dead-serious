# Practical catalogue scoring
Authored current method, following the owner's urgent request for numerical estimates from existing information rather than another research/verification pass.
## Meaning of the numbers
All nine displayed scores are ordinal integer 0–10 judgement estimates, not measurements, probabilities or scientific conclusions. Missing independent validation affects confidence and the short rationale; it does not prevent a numerical estimate.
Anchors: 0 no meaningful value/insight; 1–2 trivial, obvious or very narrow; 3–4 modest competent adaptation; 5–6 worthwhile non-obvious abstraction or useful outcome; 7–8 strong reusable insight or substantially useful capability; 9–10 exceptional paradigm/practice or importance within the stated problem. No average or weighted total decides membership.
Project scores are current product value, conditional-future total product value, technical feasibility and delivery feasibility. Future value means value if the stated goal succeeds, not likelihood-weighted value; technical and delivery feasibility are separate ordinal judgements, without a fabricated statistical horizon or probability.
Contribution scores are non-obviousness, depth of thought, transferability, current contribution value and conditional-future total contribution value. Familiar components may form a valuable transferable recipe; code volume, elapsed effort, a polished README or an output's existence is not itself creativity. No outside adoption or new experiment is required merely to estimate potential reuse.
The displayed insight/depth/transfer and inside-value columns refer to the strongest currently valuable linked contribution, selected by current inside value then depth. This is a derived view, not another stored rating or a sum of assets. A project with no identified contribution displays zero identified inside value; no asset is invented to fill the row.
## Four axes and the showcase score
The nine raw judgements are not nine independent facts, so the displayed recommendation is derived from four axes rather than summed across nine. idea is the mean of the three contribution idea dimensions; realized is max(product value now, best inside asset value now); upside is max(product if done, inside if done) multiplied by (technical+delivery)/20; delivery is the delivery-feasibility estimate.
showcase = gate × idea^0.40 × (realized+0.5)^0.35 × (upside+0.5)^0.25, a weighted geometric mean, so no column can carry a project and a weak factor degrades rather than being averaged away. gate is binary: 1 if a stranger can open the project and see something, 0 if not — private payload, nothing runnable, or a one-off with no reusable method. A caveat such as "unfinished" or "needs setup" is priced once, in delivery, never again in the gate.
Collapsing is justified by measurement, not taste. now↔inside now correlate at about 0.86 and future↔inside future at about 0.88 because the inside figure is the best asset within the product, so summing them pays the same artefact twice; max replaces the sum. The three idea dimensions correlate at about 0.91–0.96. A divergence-forcing re-score of 21 projects, each dimension argued from separate evidence with idea judged blind to delivery state, still returned r=0.93/0.94/0.94 against 0.93/0.85/0.86 for the 52 blended rows, so the fusion is intrinsic to the question: what is clever, how hard was it, and can someone else reuse it are answered by one judgement. The idea dimensions therefore enter the formula once, and remain visible per asset only as detail.
Correlated entries are handled by family rather than arithmetically: the showcase shortlist takes the best project per family, so a portfolio is not six variants of the same storage toy.
## Scope and inputs
Each scoring agent owns one project only and receives one compact generated packet from the already-collected source snapshot, contribution inventory, metadata and that project's relevant owner feedback. It reads that packet once and returns concise numeric JSON; no other project, parent-document inventory, web research, tests, builds, extra reviewer or approval loop is part of the scoring task.
An audit pass over the 21 projects with the least credible idea scores used a strict rubric — idea judged blind to whether the code runs, one clause of evidence per dimension, an explicit showability gate — and replaced those numbers while recording the previous value in each project's rating trajectory. A single blended rationale sentence per project is not paraphrased into invented per-axis distinctions; only audited projects carry per-axis evidence.
Current source descriptions, revision bindings and owner-versus-observer provenance are retained. The numerical estimates do not certify runtime correctness, security, novelty or experimental success. Human/AI effort quantities are not fabricated; an absent effort record remains unrecorded metadata rather than an invented number or a withheld score.
## Sources and projection
Current authored assessments, reasons and per-project display text live in ../result/catalogue-redesign/assessments.json. scripts/catalogue_practical.py adopts the one-project numeric outputs; scripts/catalogue_display.py derives or audits the display block and can apply an audit while keeping both sides of the change in the trajectory; scripts/catalogue_final.py computes the four axes and generates ../result/catalogue-redesign/README.md and index.html. scripts/catalogue_probe.py reproduces the correlation evidence behind the collapse.
The prior research-gated contract, scripts/catalogue_redesign.py and their tests describe the superseded research workflow and its preserved evidence; they are not acceptance gates for this immediate estimation request. No new scientific review or comparative research is implied by the current result.
## Mechanical checks
Require exact project/contribution-id coverage and integer 0–10 values in every judgement. Check the generated view contains four numeric axes plus a gate per project and no unknown score cell. Do not manufacture measurements or empirical confidence to make a complete-looking table. Every project carries what it is, who it is for, its state, what a visitor sees, how each axis was reached, what stays unverified and how its rating moved, so the scoring system itself can be reviewed from the published result rather than reconstructed from memory.
Run python3 scripts/catalogue_display.py --derive to fill display text that is missing, python3 scripts/catalogue_display.py --apply <audit.json> to fold an audit in, python3 scripts/catalogue_probe.py to reproduce the correlation evidence, and python3 scripts/catalogue_final.py to regenerate both views from the authored source without rerunning agents.
Membership/removal authority remains in ../product/catalogue.md and ../plan/catalogue-curation.md; scoring does not authorize further deletion or changes to child projects, private payloads or live work.
