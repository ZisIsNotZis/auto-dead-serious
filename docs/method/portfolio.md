# Portfolio

Three tiers, and no fact lives in two of them.

The law lives in `agent-policy/law/`, pinned as a submodule. It holds nothing about any project.

`docs/plan/` holds the portfolio: which projects the root advances, the degree of agency each runs at, what each may spend, when spending it is cheapest, and which model serves its work. It names a project's plan by path and never restates a fact from it.

A project's node document is its own plan document, inside its own `docs/`, in whatever shape that project chose. The law does not dictate that shape, because no layer above a node decides how it splits.

The test at the boundary: a portfolio row may carry a decision about a project. It may not carry a description of one. A sentence that describes a project belongs in that project.

## Two models, not one

Work that advances a project runs on the root's own model. A product's own agent calls are the product's cost, not the root's, so they are named in the portfolio row and dispatched by that name. This keeps a project from silently spending the development model on its own runtime, which is the expense that grows without a person noticing. `docs/method/models.md` holds which model is which and why the cheap one does not advance work.

## Where the spend rule lives

The law states the rule: metered spend follows the cheap window while the work is throughput-bound, and ignores the window while the work is waiting-bound. The portfolio carries the site's clock and the per-project answer, because the clock is a fact about where the work runs rather than about how agents behave.
