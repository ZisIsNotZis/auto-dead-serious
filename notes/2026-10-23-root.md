# Error notes — root, 2026-10-23

Written late: the person asked where the day's mistakes were written down, and the answer was nowhere. One note per class, the incident as an instance under it. Root's feedback path is to Policy Worker; this file is the note, the dispatch is the sending.

## 1. A question reached the person in the author's own handles

**Context.** Carrying a project's actor-pilot gate up to the person, in that project's own handles and nothing else.
**Error.** The question named the project's internal handles and nothing else. The person could not point at any noun in it: "How am I supposed to understand what does those numbers even mean, our new rule explicitly forbids this kind of naming."
**Cause.** The mechanism that let it through: a question travels up unchanged from a project's record, and nothing on the way asks "can the person point at each noun". `asking.self_contained`, `to_human.name_concretely` and `person_record.vocabulary` all forbid it, so the rule was not unclear — the check was absent, and root carried the text rather than the thing.
**Level.** The rule, not only the instance: a carried question needs a step that names every noun in the person's words before it is sent, and the note is that this step does not exist.
**Related.** Instance 2 (root doing the carrying by hand, so no second reader passed it).

## 2. Root performed the layer's craft instead of dispatching it

**Context.** The `economy.output_cap` law node, and two of its three versions.
**Error.** Root edited `agent-policy/AGENTS.yaml` directly, wrote policy prose and the law's reason, three times. The person's correction, same day: "you should let schema-worker do schema stuff, not you… you don't reach your hand into area that's non of your business."
**Cause.** Mechanism: the file was already in root's context (being read to answer a question), and editing it is cheaper than dispatching. No step separates "the file I was reading" from "the layer I may write".
**Level.** The rule: root's hand should not reach a submodule it only reads. A worker owns the law.
**Related.** Instance 1's cost was doubled by this: root carried and also authored.

## 3. A law's reason was asserted from mechanism instead of read from the record

**Context.** `output_cap._know`, first and second versions.
**Error.** "a call cut at its cap has been paid for in full" — false, billing is per produced token. Then "its answer was unusable" — false, 7 of the 42 truncated draws still matched the reference and were counted.
**Cause.** Both sentences were written from how billing *should* work, not from the 42 rows. The record that refutes them was in the same tree.
**Level.** The rule: a `_know` states a checked instance, so the read that produced it belongs beside it. The review contract caught both, so the loop held — but it held by spending two review rounds on prose a reader never sees.
**Related.** Instance 2: the node existed because root wrote it.

## 4. A stale environment fact was sent as current

**Context.** A message to a project said the database engine it measures against was absent from the box, on the strength of `which psql`, `which pg_ctl`, `/usr/lib/postgresql`.
**Error.** A postgres had been serving on 5432 the whole time, in a container.
**Cause.** The reads did not cover the surface the claim was about: a host `which` says nothing about a container's port. And the read carried no moment.
**Level.** Already closed in the law the same evening (`the_world_changes.truth.machine_fact`), and the person's words are in it. The remaining question is whether the same project's own identical error — "endpoint down since 10-19", read from the process table for a claim about a port — reached every project that reads a service.
**Related.** Not an argument for another node; a check for who still holds a port claim.

## 5. Root spent its context on work instead of on the tree

**Context.** One hour of this conversation: nine mail files read in full, submodule pins, five law commits, a product session run by root by hand to test a recipe.
**Error.** "you already used 20% context within this 1h, that's not acceptable… you are orchestrator, you don't do job."
**Cause.** Mechanism: reading is how root learns a project, and there is no rule that says how much of a project root may read before it should ask the project instead. `portfolio` says root learns a project by asking it — the rule exists and root ignored it, because reading felt faster than dispatching.
**Level.** The rule: what root may read, and when a question to the person must instead be a dispatch to the project.
**Related.** Instance 1: a dispatched question would have arrived with the project's own plain-name duty intact.
