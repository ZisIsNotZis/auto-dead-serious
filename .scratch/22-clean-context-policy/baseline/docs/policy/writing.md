# Durable and agent-facing writing

Use when creating or reviewing durable documentation, `AGENTS.md`, associated policies, or policy routing. Apply these tests to this file too; ordinary code-preserving work does not require invented documentation.

- **Truth and home:** product decisions need a traceable source such as an explicit user decision or accepted requirement; an `approved` label alone is not proof. Mark consequential interpretation provisional, resolve conflicts at the authoritative decision, and update changed behavior or contracts before or with implementation. Keep one authoritative home and link instead of copying facts. Retain raw source only when provenance warrants safe storage; it is not automatically operational truth.
- **Placement:** project decisions belong in project `docs/`; verified workspace facts and commands in `WORKSPACE.md`; core agent boundaries in the owning `AGENTS.md`; conditional methods in its associated policy files; transient evidence in work records. Create reusable skills, roles, or automation only for demonstrated need. Paths follow the owning `AGENTS.md` versus target-project distinction in the core. Do not infer personality or reliability from user interaction.
- **Agent-writing test:** for each proposed instruction, identify the observed situation, the decision it changes, the action, and a checkable result. Distinguish hard safety boundaries from context-dependent advice. Delete a line whose removal changes no decision or safety boundary; replace duplicate formulations rather than appending a clarification. Use concrete scenario rereads for ambiguity. Size is a diagnostic, not a target that justifies deleting safeguards.
- **Policy edits:** wording-only fixes need a scoped reread, reference check, and `git diff --check`. Authority, safety, user-intervention, routing, or compatibility changes also need a durable rationale, before/after size, scenario check, and independent fresh-context review when feasible; if unavailable, record a scoped self-review and its limit rather than inventing user approval. Keep live references unique and update the owning index when merging files. Historical tickets need not be rewritten if their meaning remains recoverable. Policy must work without optional skills, a particular model, or an external tracker.
