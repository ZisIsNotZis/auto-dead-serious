A reader cannot resolve when "the execution phase" starts, and the doc's own `one_name_one_thing` (line 107: "A name drifting from A to B to C is the worst cognitive trap") is broken. Smallest fix: replace "the execution phase" with "the advance phase".

2. **Undefined term "the instruction records"** (criterion 1). AGENTS.yaml:129 `split.preflight`: "read the target and the state needed to attribute the change, plus the instruction records, and nothing else." The term occurs exactly once in the file (`grep instruction` → lines 15, 45, 129, 163, none defining records). 4. **"gate" carries two senses and is never tied to "milestone"** (criterion 1, 5). AGENTS.yaml:211 `ship_at_gate`: "Deliver the real artefact at the agreed user gate" vs AGENTS.yaml:309 `run_the_gates`: "Run the target project's check gates, meaning CI and its tests". Smallest fix: one sentence equating user gate and milestone, and rename one of the two senses (e.g. "check gates" → "check steps").

11. **Schema contradicts the renderer about `@key`** (criterion 3). AGENTS.schema.yaml:4: "A secondary cause appears inline as @key and is never parsed by the program." render_policy.py does parse them: `REF_RE` (line 24), collected at line 53, validated at lines 59–62 and turned into a hard failure ("dangling @ref"). Smallest fix: say "never rendered, but checked for dangling targets by the renderer".

12. **Key-uniqueness enforcement is partial, and one key-shape clause is dead code** (criterion 8). `read()` uses `yaml.safe_load` (line 30), which silently keeps the last of two identical keys inside one mapping; `check()` can only see the parsed dict (lines 55–57), so a duplicated key in the same mapping is undetectable and the earlier rule text is lost while the check prints "checks passed". AGENTS.schema.yaml:4 claims keys are "globally unique". Conversely, `if not KEY_RE.fullmatch(key) or " " in key` (line 51) can never be true for the second clause, because `KEY_RE` (line 23) already excludes spaces (and the schema's `additionalProperties: false`, line 20, rejects them first). Smallest fix: load with a `SafeLoader` subclass that raises on duplicate keys; drop the redundant space clause.

13. **Dangling-ref check can pass while the target is missing from the render; `@` detection is over-broad** (criterion 8). `known = {k.rstrip("*") for k in keys}` (line 59) strips the hidden-key marker, so `@emphasis_by_evidence` would validate even though `emphasis_by_evidence*` is never written into AGENTS.md; and `REF_RE` `@([a-z0-9_*]+)` (line 24) matches any `@word`, so e.g. `user@example.com` in a `_text` would report a false dangling ref. Smallest fix: build `known` from rendered keys only and require a word boundary before `@`.

14. **Two rules pull opposite ways on outdated code** (criterion 3). AGENTS.yaml:251 `docs`: "Code may carry history and quality problems; docs may not." vs AGENTS.yaml:295 `hard_delete`: "Anything outdated is hard-deleted from the latest revision, never commented out, branched or kept behind an if/else." A reader keeping a legacy code path cannot tell which applies. Smallest fix: scope one of them ("code may carry imperfect code, not dead code").
