# small-tail-b — lessons from 16 migrated projects

Slug: `small-tail-b`. Coverage: io_uring-echo-server, http_mock, grammar, fring, disk, dinoseg,
dino.py, cznn, cz_noidea, cz_einn, cz_bert, cvorat, cuda, beam, pi-keys, docs.
Every project below was read in full (root `*.md`, `docs/project-status.md`, and the only top-level
`*.txt` files). Nothing was written inside any project. Findings marked *inference* are my reading,
not a file's statement. Verified absences (a file the docs claim but that is not present) are
noted where they matter.

## io_uring-echo-server

- [know-how] README.md#build - the checked-in `makefile` does not build the project it names (the `io_uring_server.c` rule is commented out; the zero pair has no rule), so the README holds the only working build recipe, as five explicit `gcc` lines - policy candidate: when the build store stops carrying the fact, the README becomes the store, and the two drift silently.
- [pitfall] README.md#build - `make` depends on `-march=native` and on `liburing.a` being on the linker path, so the documented default build fails and the reader must fall back to the gcc lines - project-specific, but the shape is general: a broken default path costs every new reader one failed command.
- [pitfall] README.md#docker - the Dockerfile is `FROM alpine` + `ADD srv cli` with no `CMD`, and the binaries are glibc-linked, so the image can never have run (`alpine` is musl) - project-specific.
- [pitfall] README.md - the client's `HOST`/`PORT` were hardcoded to a Docker-internal address and were replaced with env vars during publication; the zero client needed `getaddrinfo` instead of `inet_pton` - policy candidate: a hardcoded internal address is both a portability defect and a leak of internal topology, so it belongs in the same publication pass as the credential scan.
- [project rule] README.md#why-it-exists - the README's first duty is to say the repo name is aspirational: "The name says 'echo server', but **nothing here echoes**" - already covered by resources.efficiency.one_name_one_thing.
- [doc method] docs/project-status.md#evidence - the best status record in the group: every claim names the file and the verification ("compiled against `liburing 2.5` and probed on loopback — returned `hello` then closed the connection") - policy candidate: this is the achieved form of a status doc, and the general policy has no such artefact (a claim without its verification is not evidence).
- [doc method] docs/project-status.md#boundaries - the verification environment is recorded ("`liburing` headers extracted locally from `liburing-dev 2.5-1build1` (the package was not installed system-wide)") - already covered by proof.execution.bind_to_revision.

## http_mock

- [project rule] README.md#status - the label separates the dependency from the method: "The PyTorch calls themselves are not deprecated ... but the *approach* is decades-of-iterations stale by 2026" - policy candidate: change.docs.outdated says age decides nothing and value decides, but here the two ages disagree (API is current, method is not) and only the method matters to a reader.
- [doc method] README.md#how-to-run - "Not run here during migration (read-only review)" - the run instructions are explicitly declared unexercised - already covered by resources.environment.readme_tested.
- [pitfall] README.md#status - `http_mock_4.ipynb`'s first cell is truncated mid-edit (unterminated string literal) and was archived as-found, so "open and Run All" fails on the file the README describes - project-specific; the general point is that an archived file which cannot even parse must be flagged as such, not listed as a variant.
- [doc method] docs/project-status.md - 22 lines of migration boilerplate whose status section says only "See `README.md` for what it is and an honest status line" - policy candidate: a required file filled with a pointer to another file claims a record it does not contain; seven of these fourteen projects share this file verbatim apart from the source path.

## grammar

- [pitfall] README.md:194 - "**No written-up results.** No paper, no report, no README-style notes, no tables, no plots"; the project's hypothesis had to be reconstructed from the corpus path and the 90-way classifier - policy candidate: proof.execution only requires evidence to survive for recomputation; a research artefact whose *reading frame* (hypothesis, which run, which config) was never written cannot be audited at all without redoing it.
- [pitfall] README.md:195 - "All cell outputs were cleared before archiving. The `10*.txt` logs and four one-line annotations are the entire recorded outcome" - policy candidate: clearing outputs deleted the evidence (loss curves, tables, printed accuracies). This is an archiving convention, so it belongs in the policy, and it contradicts `cz_bert`, which kept its outputs on purpose (see below).
- [pitfall] README.md:81 - the metrics are appended to generically named files (`open('10.txt','a')`, `10b`, `10c`) by a dozen different notebooks, so a surviving float cannot be attributed to the configuration that produced it *inference* - policy candidate: a run record must carry its configuration, or an append-only log produces unownable numbers.
- [pitfall] README.md:95 - the corpus `../dat/py/all.90` "is not included here and is not recoverable from this directory" and nothing regenerates it, so no notebook can be re-run end-to-end - already covered by resources.environment.keep_what_costs.
- [pitfall] README.md:237 - "a naive credential-gate regex ... finds **nothing** in either the source or the published copy"; the leak was found only with a JWT-shaped scan (a signed SSO token carrying a phone number and an ADMIN role) - already covered by proof.execution.only_authorized, but the concrete case generalises: a "clean" scan is evidence only about the pattern classes the scan contains, and the gate must be widened by shape, not by keyword.
- [project rule] README.md:224 - the token was removed rather than genericised because it is signed and carries identity, and the README says the source token "should be treated as compromised and rotated if it was ever live" - already covered by intent.risk.secrets.
- [know-how] README.md#relationship-to-nnpy--cznn - the relation to the author's `nn.py`/`cznn` library was checked and recorded as negative, with the evidence (no `.py` files at all, no notebook imports `nn`) - policy candidate: a checked-and-negative cross-project relation must be written down, because otherwise the next agent re-derives it from scratch (this cost real reading of 17 notebooks to establish).
- [detour] README.md#which-notebook-should-i-read - `Untitled1.ipynb`/`Untitled1-Copy1.ipynb` are a side experiment (distilling a dense `Conv1d(16,16,3)` into separable stacks by MSE) and `Untitled4.ipynb` holds a half-written `EncDec6` with only two stages defined; the README keeps them but grades them - project-specific.

## dinoseg

- [pitfall] README.md - `dinoseg2.py` imports `from util import vcache, chunk` and "**`util.py` is not present in the archive** — that version cannot run as-archived" - project-specific in effect, general in shape: a superseded snapshot kept for provenance must be labelled non-runnable, and the missing module is only noticed by reading the import.
- [know-how] README.md:127 - `dinoseg2.py`'s `Prd` applies its confidence cut as `cnf < 0` on raw logits, "which is effectively no cut — a leftover threshold bug"; the fix in `dinoseg3.py` uses the kNN margin `< .8` - non-obvious because the code runs happily and still produces masks, so nothing fails, the filter just does nothing.
- [pitfall] README.md:134 - the env-override line contained a no-op bug (`i is os.environ` for `i in os.environ`), so the documented override never fired - already covered by resources.environment.readme_tested.
- [doc method] README.md - three snapshots share one on-disk contract (`<image>.<H>,<W>,<EMB><dtype>` for patch tokens, `<image>.99,3B` for up to 99 labels), and the cache is written next to the input images so the tool fails on a read-only or shared dataset directory - project-specific: the sidecar contract is the only real interface, and it is documented in prose rather than declared anywhere in the code.
- [detour] README.md#the-three-files - three successive snapshots of one program, each replaced for a stated reason: `dinoseg.py` retrained one linear layer on every click and cached in memory, `dinoseg2.py` moved to a float16 disk cache, `dinoseg3.py` added the `mtime`-invalidated cache graph so a label edit retrains only its dependants - know-how: the invalidation graph, not the model, is what made it usable.

## cz_einn

- [project rule] README.md#deprecation-note - "The *files* were last saved 2026-02-13, but the idioms are roughly five years older than that date. The status label reflects the idioms, not the mtime" - policy candidate: mtime is not evidence of currency, because a copy, a re-save or a git squash resets it while the content stays stale (the prompt for this project was exactly that kind of re-save).
- [project rule] README.md:311 - relative external paths were left byte-identical on purpose: "the `../tmp/news2016zhMin100.H` strings *are* the evidence of what the corpus was and where it lived. Rewriting 40+ duplicated `Dat` class definitions ... would destroy that record", with the `CZ_EINN_CORPUS`/`CZ_EINN_SOURCE_DIR` mapping documented instead - policy candidate: redaction must not destroy provenance; genericise identifiers and secrets, and never evidence of what the input was.
- [doc method] README.md#canonical-regeneration-recipe - the corpus recipe is preserved verbatim and its known gap is stated: step 2 consumes `news2016zh.H`/`.txt` which step 1 does not produce, and "the filtering threshold is `max_freq / 100`, which is where the 'Min100' in the filename comes from" - marked as read, not run - policy candidate: a documented recipe carries both its provenance (read vs executed) and its known gap, or it becomes a command that never worked.
- [doc method] README.md#security-scan - the scan is quoted with its exact command, its exit code (`-> no matches (exit 1)`), and the note that the employer-domain alternative is written as a placeholder "so that this document does not itself trip the rule it documents" - policy candidate: the record of a check must not violate the check, and the negative result of a gate is worth reporting as explicitly as the positive one.
- [pitfall] README.md:169 - some cells pair `Embedding(684, ...)` with a `685`-wide output layer; "that off-by-one is unexplained in the archive and may be a padding class or a bug. Left as found." - already covered by change.docs.no_fabricated_defaults.

- [know-how] README.md#expected-shape-of-the-corpus - the corpus is a raw uint16 little-endian character-ID stream (`.H`) plus a NumPy UTF-32 `U1` decode table (`.txt`); reading `.H` as signed `int16` is byte-identical for any ID below 32768 and the whole vocabulary is - project-specific know-how an agent could not guess from the filenames.
- [detour] README.md#the-notebooks-in-order - the string-DSL was dropped after `einn.ipynb` in favour of functional generators (`einn2*`), then dropped entirely for real classification and autoencoding tasks; `einn5-autoencoder-Copy17.ipynb` is "an unrelated branch that pulls in a pretrained `resnet26d` (absent from the repo) — an experiment that did not go anywhere" - know-how: the README also records *why* the idea expired (done properly by `einops` and `torch.fx`), which is what stops a future agent re-running the same bet.

## beam

- [pitfall] README.md:16 - the only recorded build line "is preserved as a trailing comment in `beam7.cpp`, `beam8.cpp` and `beamUnknown.cpp`; it references a local llama.cpp checkout and local BLAS build directories that are not part of this directory. No self-contained repro exists." - policy candidate: a build command that lives in a source comment is not a documented command, it is a private note; the fact belongs in an artefact a reader can resolve (change.docs.references_resolve only covers commands that *are* documented).

- [detour] README.md#one-line-what - eight files (`beam.cpp` … `beam7.cpp`, then `beamUnknown.cpp` seven months later) are the record of "iterating to find a correct-and-fast sequence-reuse strategy" over `llama_kv_self_seq_cp`/`seq_rm` and `common_sampler_clone`; the last file is named `beamUnknown`, which is itself the outcome - know-how: the iteration count is the finding, and it says the KV-cache sequence-reuse strategy had to be measured, not reasoned about.
- [project rule] README.md#license-note - the publication route is named: publishing "as part of or alongside llama.cpp is the natural and license-compatible route", because the surrounding scaffolding is llama.cpp's MIT example framework, whereas a standalone repo would inherit a licence obligation - know-how for a publication whose code is 90% another project's framework.

## pi-keys

- [project rule] README.md:25 - the README declares an explicit input contract and then says the code "does not validate or repair them": distinct keys, no key in two pools, the singular variable initially equal to the pool's first key, and the model must really authenticate through that variable (`--api-key`, stored `/login` credentials and literal configured keys all break it) - policy candidate: the general policy has no slot for a declared trust boundary, and this one is what tells a future maintainer which failures are not bugs.
- [project rule] README.md:78-80 - the integration test is opt-in (`PI_KEYS_SMOKE=1`), hermetic (isolated temporary settings and a local fake OpenAI-compatible server, dummy keys only, "It makes no external API calls"), bounded, self-cleaning, and the claim is pinned: "Verified against Pi 1.1.0. Broader provider coverage and indefinite quota recovery are not claimed." - policy candidate: this is the achieved form of a runtime-verified claim (pinned version, faked peer, stated non-claims) and the general policy's proof sections describe the shape without this much concreteness.
- [know-how] README.md:50 - "**Rotation does not make an error retryable.**" Pi's classifier refuses automatic retry for quota/billing phrases (`insufficient_quota`, `quota exceeded`, `billing`) even inside a 429, and a bigger `maxRetries` does not change classification; the extension "does not rewrite errors to bypass that policy" - strong know-how: the obvious move (raise the retry budget) does not work, and the classifier, not the count, is the gate.
- [know-how] README.md:67 - overlapping model calls sharing a pool "are not coordinated: the hook resolves authentication after failure, rather than recording the credential each request actually used", so only ordinary sequential requests are supported - knowing which concurrency assumption a hook depends on is what stops a false bug report.
- [project rule] README.md#development - this is the only project in the group with tests, no runtime dependencies, and no `docs/project-status.md` at all - project-specific correlation worth noting: the fifteen archive projects all carry a status file and no tests, and the one live project carries tests and no status file.

## docs

- [pitfall] docs/people.md:6 - the user record stores psychological labels with no occasion, quote or evidence: "Temperament and reliability: delivers ideas in large fragmented bursts (sometimes 10+ points at once, occasionally self-contradictory) ... corrects course decisively when reviewing reports" - already covered by change.docs.no_mood_labels, and this file is the precedent that shows why the rule exists (a later agent cannot tell a pattern from one bad session).
- [pitfall] docs/people.md:3-5 - role, expertise and working style are all unmarked agent inference about the user, with none of the coordinates `decisions.provenance` and `change.docs.fact_record` now require (`author`, `origin`, `status`, `evidence`); "expects the agent to formalize naive phrasing into professional terms" is a reading, not a quotation - already covered by change.docs.split_authorship.
- [doc method] docs/people.md - the file sits in a directory named `docs/`, the name the policy's `docs` layout reserves for per-layer document folders, and it holds the user model that `AGENTS.yaml` assigns to `PEOPLE.yaml` beside the policy; the same name therefore means two different things at two levels, and the user model risks having two homes - policy candidate, *inference*: I could not verify whether `PEOPLE.yaml` exists, because reading the workspace root is outside this assignment's scope.

## Top 5 by value

1. **Archived notebook outputs are evidence, and clearing them destroyed the only results** (`grammar/README.md:195` "All cell outputs were cleared before archiving" against `cz_bert/README.md:75` which kept them on purpose). Two sibling projects chose opposite conventions; in `grammar`'s case the choice left three float logs and four one-line annotations as the entire outcome, so the archiving convention must be a policy rule, not a per-project habit.
2. **Redaction must genericise identifiers and never evidence** (`cz_einn/README.md:311` - the `../tmp/...` corpus paths were left byte-identical because they are the record of what the data was, with an env-var mapping documented instead). This is the only project that reasoned about the cost of rewriting paths, and it is exactly where a reflex "genericise all paths" pass would have destroyed the provenance the migration existed to preserve.
3. **A status label must name its axis: stale idioms / missing environment / unmaintained** (`cz_einn/README.md#deprecation-note` "the status label reflects the idioms, not the mtime"; `disk/README.md#status` "unreproducible rather than outdated"; `cuda/README.md#status` "archive_only in tone even though the code is publishable"). Three independent projects paid for this, and the existing `change.docs.outdated` rule ("Age decides nothing; value decides") does not separate them, so a reader cannot tell what to do next.
4. **A passing gate is evidence only about the pattern classes it contains** (`grammar/README.md:237` - a credential regex found nothing while a JWT-shaped scan found a signed SSO token with a phone number and an ADMIN role; `cz_noidea/README.md:11` - Apache-2.0 licence text pasted into a notebook that no `LICENSE`-file check would see; `disk` - five third-party SDK files carried in by a verbatim copy). One publication pass over this group needed three pattern classes the gate did not have (secret shape, licence text, authorship), which is a policy-level statement about what "the scan is clean" may be used to claim.
