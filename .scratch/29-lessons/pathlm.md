# pathlm

Repo: `/home/z/vibe/pathlm` — a research-wiki + single-experiment playbook for "LM compute-path design
space", built on top of a closed PathLM project (25 execution tickets). 51 cells, 79 experiment dirs,
one shared engine (`pathlm/`), one shared 4090. It has two independent full-repo adversarial reviews
(`.scratch/49-adversarial-review/REPORT.md`, `.scratch/50-critical-audit/*`), 7 per-axis audits
(`.scratch/55-review/*`), and a doc-SSOT migration (ticket 56). Richest source of paid-for lessons I
have seen: the failures are dated, quantified and already written down.

## know-how

- [know-how] `docs/methodology.md` §3 - a compute exchange rate must be the **analytic** `R=(1+γ)/(1+τ)`; the measured wall-clock width-(1+γ)/width-1 ratio `c_wall` contains kernel fallback, launch overhead and external occupancy, and substituting it produces conclusions that drift with the environment. Corollary in `docs/playbook.md` 定律 8 边界: never report a "scale flip" before ruling out caliber and scale mismatch (wall-clock/FLOPs mixing, unequal steps or annealing schedules, unequal token budget, absolute loss across different contexts) - `policy candidate`
- [know-how] `SCHEMA.md` §10 - **identity init ≠ zero init**: the natural way to make a gated change start strictly equal to the baseline is zero init, but at that saddle the gradient can also be zero and learning stops permanently. Correct is **one-sided zero** (output side zero, input side random); measured `W1~N(0,0.02), W2=0` escapes to |W1|=5.34 within 200 steps while `W1=W2=0` is still all-zero - `policy candidate`
- [know-how] `SCHEMA.md` §19 - **local-prior resistance**: on data with very strong local statistics (enwik8) a small model simply does not need distant context, so "the model doesn't need it" is misread as "the mechanism cannot carry it". Any long-range/memory/compression conclusion must be double-run on a synthetic task local priors cannot fill (random key–value recall, induction) and the synthetic result wins; the synthetic task's own noise can exceed the effect, so its domain of validity must be labelled - `policy candidate`
- [know-how] `SCHEMA.md` §17.16 - a two-point trend requires both points at the **same relative scale** and both non-degenerate, with the non-degeneracy pinned by a unit test (window 256 at T=256 is the identity operator); if a second real point cannot be built, report a single point rather than padding with a degenerate one - `project-specific`
- [know-how] `.scratch/11-retry-matrix-validity/evidence/README.md#Model-stacking assessment` - the `(M,B,T,d)` process-stacking rewrite was measured and abandoned: solo 39–48 ms/step vs 3-way 98–113 ms/step with 5.75 GB/run capping concurrency at 3–4, and doubling batch cost only 1.5× time ⇒ ~25% of per-step cost is fixed overhead, capturable by **raising batch size** with no code change and no grouped-GEMM rewrite - `project-specific`

- [detour] `.scratch/50-doc-ssot/JOURNAL.md` C15 - the root scope declared "we do not do combination experiments", but the tree actually contained a 2×2 (carry × depth supervision), a GQA+carry+window ladder and head-sharing × quantisation; the declaration was rewritten to "default blank **with registered exceptions**", i.e. an explicit non-goal that reality contradicts must be corrected rather than tolerated - `policy candidate`
- [detour] `.scratch/50-critical-audit/A-AUDIT.md` §3 "开倒车清单" - three standard-kit misapplications: ALiBi was used with one fixed slope shared by all heads, so "all heads pushed local, no head specialisation appears" was a necessary consequence of the setting, and length extrapolation (the point of per-head slopes) was never tested; sparsity was tested at T=256 where attention is 14.3% of MACs, i.e. structurally guaranteed to lose; and the sparse implementation kept dense scoring, so the advertised −43.75% FLOPs never materialised (measured implementation saving = 0); the general form is playbook 定律 10 "what must the design satisfy for this mechanism to have room to act" - `policy candidate`

## project rules

- [project rule] `SCHEMA.md` §20 - full GPU mutual-exclusion protocol with **self-healing stale-lock reclamation** (holder_pid dead, or no holder_pid and lock age >15 min), `rm -f` contents then `rmdir` (a lock dir with `holder_pid` cannot be `rmdir`ed), always a `sleep` on the retry path, a 10-minute wait cap, "report on timeout, never kill another agent's process", and the explicit ban on liveness checks by process name ("`pgrep -af "train|run.py"` matches the waiter's own command line, so a stale lock is never reclaimed"; this incident is almost certainly where the general rule came from) - `already covered by scheduling.never_block_on_a_resource`
- [project rule] `SCHEMA.md` §20.1, §20.2, §20.3 - multi-arm drivers must release and re-take the lock per arm with a ≥60 s window (whole-run holding allowed only under 10 min); a ≤2 min/≤1 GB inference job may queue-jump when ≥3 GB is free **but must be registered as a one-off concurrency exception with before/after free-memory readings**; the 5 GB courtesy line is explicitly "not a scientific constraint" and when it conflicts with keeping two arms' recipes field-identical, the recipe wins and the deviation is booked (per-arm `peak_gpu_mem_mb`, pre/post `nvidia-smi memory.free`, explicit disclosure); when under external load, shrink steps to keep an equal budget between arms and declare "Nk snapshot, not comparable with Mk" - `policy candidate`
- [project rule] `SCHEMA.md` §22, §22.8 - for shared files: one writer per file; a code-edit lock held only in the read-modify-write window with a fixed **code-then-GPU lock order** to avoid deadlock; declare anchors before editing, append locally, never rewrite a block; after the change, grep back that every other line's markers still exist and never `git checkout`/`stash` someone else's work; record the shared file's sha256 and disclose overlapping caliber in the report; best answer is a new module with minimal wiring. §22.8 adds that dispatch must also do a **capability-surface analysis** (does the engine support each flag and each combination), and if not: lower the contract to a faithful sub-problem with the untested factor declared, or make "make it combinable" its own item with tests - never "later", never change the engine without authorisation - `policy candidate`
- [project rule] `SCHEMA.md` §14b, §14 - review must be scheduled **after** execution as a dependency barrier (same wave only with an explicit "poll for these artefact paths first" instruction); a same-wave no-op review counts as neither reviewed nor accepted; and the reviewer's first checklist item is "was the criterion line changed against the contract text - if yes, fail" - `policy candidate`
- [project rule] `SCHEMA.md` §23 - the seven questions a cell must answer before it may stop: was prior art checked and written; is the criterion the strictest one with honest opponents and sabotage/causality/activity guards; were the wrong-kinds of control all tried (equal parameters, equal compute, equal bytes); were at least two scale or budget points probed; was the falsification path walked; are untested items listed as "next minimal experiment + cost"; did review pass (AGENTS.md has no per-unit "definition of done" checklist of this kind) - `policy candidate`
- [project rule] `SCHEMA.md` §15, §16, §17.15 - a gain claimed for a structural change needs an arm with **exactly the same parameter count** minus the structure (if the difference is inside the noise band, attribute it to capacity/reparameterisation); any snapshot gain needs same-method loss slopes plus one ≥2× longer training point (measured: Δ −0.0812 at 12k shrank to −0.0463 at 24k, i.e. 43% of it was convergence speed); and the convergence gate must sit on **the loss that decides the criterion**, not on the aggregate (filler tokens dominate aggregate CE and hide the task-relevant underfit) - `policy candidate`
- [project rule] `SCHEMA.md` §4, §12, §11, §21, `docs/methodology.md` §9 - single-factor iron law with exactly one declared exception (when the single factor cannot act alone, add the current mainstream SOTA non-standard factor and account for its influence); combinations are blank **by explicit declaration**, `deps` records coupling only and grants no combination licence; three reconciliations (arithmetic bound, task identity, caliber) must pass before a favourable number enters a conclusion, and a failed reconciliation means rewriting the analysis to the correct current state rather than stacking an ERRATA; the criterion compares against a same-cost or cheaper honest opponent (self-loop), never against an oracle; and the prior-art triage is (a) industry solved ⇒ write the conclusion and do not run / (b) our setting is materially different ⇒ run and state the increment / (c) cannot find out ⇒ record as "memory, unverified" and **do not** use it to skip work - `policy candidate`

## doc method

- [doc method] `AGENTS.md` §2.1, §2.2 - the repo runs two document classes with two rule sets: **fact docs** (SSOT — declarative present tense, no dates, no "was A then B", no changelog/ERRATA/incident narrative, one home per fact, every other place a pointer only, and a fact doc may not use a log's narrative as its basis) and **log docs** (`.scratch/**`, `.scratch/doc-log/**`, optional `JOURNAL.md` — dated, append-only, explicitly not authoritative, conflicts resolved in favour of the fact doc with a note). The doc-SSOT migration physically **moved** process narrative out of the fact docs into a log - `already covered by change.docs.ssot_boundary`
- [doc method] `.scratch/56-restructure/TICKET.md` §5.2-5 - retiring a generated wiki is a two-step move, not a delete: `catalog.yaml` was marked retired in its tooling **but deliberately left in place** through the migration window because its `local:` blocks were the content source the axis workers had to migrate from, and only afterwards was the set archived to `archive/wiki-legacy/` read-only; the hard constraint driving this was "do not lose any research evidence" - `policy candidate`
- [doc method] `.scratch/doc-log/m1-lock-caliber.md` - a fact-doc body that had hardcoded "231 s" could not match both of the two artefacts produced by different runs of the same cell (231 s and 270 s); the fix was to strip the number from the prose entirely and leave **only a pointer** to the artefact plus a log section holding the dated readings - `already covered by change.docs.citation_not_value`
- [doc method] `archive/README.md` - the archive's entrance carries a mandatory warning block listing the stale-caliber traps ("all early published taxes are 1.1-epoch upper bounds", "cross-engine controls make attribution inseparable", "Δ < 0.014 not orderable", "`docs/` has been redefined in this repo") and distinguishes two deletion kinds: a **merged** cell's experiments were moved into the surviving cell, a **deleted** cell's evidence stays under `dropped/` untouched; the general form is that an archive needs a reader-facing warning about the caliber of its numbers, and deletion keeps the evidence while marking the container read-only - `policy candidate`
- [doc method] `.scratch/57-program/FRAMEWORK-DECISIONS.md` §0 - six independent axis-lead sub-projects, working independently, converged on the same three undecidable questions (which noise band judges two numbers; does the baseline count; may the shared engine be modified), and **not one chose for itself** — each reported upward; the result was one aggregation ticket for a single funder decision. The band question alone (C1) touched all six axes. The policy-relevant reading: when several concurrent units independently hit the same undecidable question, that is a signal the governing policy is missing a rule, and the response is one central escalation, not per-unit guessing - `policy candidate`
- [doc method] `.scratch/49-adversarial-review/REPORT.md` P2 - the status surface had gone stale (`STATUS.md` said ticket 42/394 tests, actual 47/595), a generated page was internally self-contradictory on one screen (same page declared "explicit memory slot has zero experience" and announced "first validation holds"), and entry-level strong claims coexisted with end-of-file downgrades - `policy candidate`

## Top 5 by value

1. **Commit and staging hygiene** (`.scratch/50-doc-ssot/JOURNAL.md`): four independently paid-for incidents — a silently non-matching bulk edit followed by a commit message claiming success, shell-executed backticks rewriting a message, `git add -A` sweeping a running sub-agent's work, and `2>/dev/null` hiding a failed `git add` that made two directories invisible while the message claimed delivery. `AGENTS.md` currently has *no* commit or staging rule at all, and this one incident was rated P0 by an external review.
2. **A noise band is per-cell and per-metric; there is no global floor** (`.scratch/50-critical-audit/A-AUDIT.md` §4-①): the repo promoted one source's explicitly cell-dependent seed spread (0.0001–0.0138, "no single global floor") into one tree-wide ordering threshold, then made every "significant" call at 1.05–1.19× of it, and it took a funder decision across six axes to untangle. The general policy should say a threshold is only valid where it was measured, and that a single-arm spread is not a two-arm difference band.
3. **A single point may not be extrapolated into a cumulative claim** (SCHEMA.md §24.11): the repo's own most expensive accounting error — a ≤0.004 single-distance reading recorded as "safe discard radius", against +0.212 bpc for the cumulative configuration that was 15× worse. The general policy has nothing that forbids turning a shape into a sum.
4. **A passing gate is not acceptance, and a check must be shown able to fail** (`.scratch/49-adversarial-review/REPORT.md` A7 + SCHEMA.md §24.10/§24.12): the repo's machine gate checked document shape only, so 50 fake `@ticketNN` anchors passed and "33 judged" was read as 33 accepted conclusions; separately a reconciliation script iterated a nonexistent key and reported green, and a producer-side key rename broke the documented entry point while `pytest` stayed green. Worth generalising as: prove reachability by constructing the input that must fail, and run the documented entry point rather than only the test suite.
5. **Review ordering and criterion lock** (SCHEMA.md §14b/§14): a review scheduled in the same wave as the work it reviews produces no-op verdicts that must not count as reviewed — and a criterion line changed against the contract text is an automatic fail. `AGENTS.md` requires fresh independent review but says nothing about the dependency barrier or about freezing the pre-registered line.
