## Findings

### Pitfalls

- [pitfall] `.scratch/incident-20260930/README.md` — an untracked root `conftest.py` (221 B) carried a `pytest_runtest_makereport` hookwrapper setting `rep.outcome = 'passed'` for every failing report, so "any bare `uv run pytest` in this repository while that file existed would have reported green regardless of real failures"; attributed to the project's own verifier lane writing a relative path with the repo as cwd. Fixes: `tests/unit/test_repo_integrity.py` fails the suite on a stray `conftest.py`/`sitecustomize.py`/`*.pth`, and probe fixtures go to an absolute path. — **policy candidate** (a green suite is not evidence until the gate's own environment is checked; fixtures get absolute paths).
- [pitfall] `docs/STATUS.md:84` (§1a) and `:368` (§8c) — the corpus task repos shipped a stale `.pytest_cache` holding **the grader's own test node ids**, the mature-agent baseline "visibly read it", and a whole claim-rule measurement was retracted as "a leaked-exam measurement"; re-measuring without it raised the review tier's false claims 10 → 13. — **policy candidate** (before measuring an agent against a hidden suite, check the fixture does not carry the answer key, including caches).
- [pitfall] `docs/STATUS.md:286` (§8) + `.scratch/26-pi-maxed/issues/26-pi-maxed.md` — the baseline was run with `--thinking off` because the temp model entry declared no reasoning support ("`--thinking max` would have been silently clamped too") and on an 8192-token server; the concluded "development capability is a TIE" was wrong, the corrected arm fixes 27/40 not 21/40. — **policy candidate** (a knob your own harness silently clamps invalidates a comparison; verify the baseline's configuration is not throttled by your setup).
- [pitfall] `docs/STATUS.md:505` (§8e) + `.scratch/28-three-requirements/issues/parity-forensics.md:423` (§4) — our wall-clock was measured under 4-way concurrency (26–34 s/task) and pi's sequentially (131 s/task) and printed side by side as "ours vs pi's"; the same forensics shows a 40-task N=1 run carries ±1.4 tasks SD (±2.0 on a difference), so the 24-vs-27 gap is ~1.5 SD. — **policy candidate** (numbers from different conditions are not comparable; call a difference only above the measured noise band, and state the seed count needed: 9 seeds/arm for parity-within-margin, 17 to claim a win).
- [pitfall] `.scratch/28-three-requirements/issues/parity-forensics.md:459` (§5 D1) — in three parity losses a **grader-passing revision was thrown away inside the run** (T-28 verified: the discarded revision passes 4/4, the delivered one fails 4/4); five of forty runs "delivered nothing" (byte-identical source, whitespace-only, one trailing newline). — **policy candidate** (before handing over, assert the delivered artefact differs from the baseline in every artefact the request names; a no-op delivery is a failure, not a pass).
- [pitfall] `docs/STATUS.md:84` (§1a) — the full stack "failed T-01, which `raw` fixed", and the note says it plainly: "The iteration can talk the model out of a correct one-shot fix." — **policy candidate** (added machinery can cost correctness; keep a documented raw baseline and ablate against it).
- [pitfall] `docs/DESIGN.md:559` (§10.8a) + `docs/STATUS.md:180` (§4 limit 1) — two verifications authored by the same model from the same goal text agree **because** they share the misreading: own test asserts `result() == 100`, independent test asserts the same, fix returns 100, review approves, harness claims, grader fails. "No deterministic in-process rule can catch it without a GROUND-TRUTH ORACLE." — **policy candidate** (corroboration must not come from the same generator given the same inputs; agreement is not independence).
- [pitfall] `.scratch/26-pi-maxed/issues/26-pi-maxed.md` (T-10's independent test, quoted verbatim: `with pytest.raises(IndexError): next_bin(empty_stock)` for the crash the request asks to remove) + `docs/STATUS.md:368` (§8c) — 8 of 11 missed wins were blocked by `independent-test-red-on-final` because the model's own verification **asserted the pre-fix behaviour**; the fix is a desired-state rule appended to the test-authoring prompt. — **policy candidate** (when you delegate a test to the same weak model, tell it to assert the desired end state, never the reported symptom; then check that the test is red on the fix, not just red on the bug).
- [pitfall] `docs/STATUS.md:180` (§4 limit 8) + `docs/DESIGN.md:325` (§10.3) — the claim rules were hardened one branch at a time; rounds 2–5 each closed the branch they were written for and "the next verifier round found the same hole in a sibling branch", so the fix became ONE `claim_decision()` guarded by a structural AST test. — **policy candidate** (a gate that exists per-branch will be reopened in the sibling branch; one decision point plus a machine check that no other path can produce the outcome).
- [pitfall] `.scratch/26-pi-maxed/issues/26-pi-maxed.md` ("### T-01, step by step") + `docs/FLOW.md` §5 — the write guard refused the frozen file (`grader-owned path`), the loop counted six identical attempts and exited on `same-verdict tail`; nothing told the model which files it *may* write, and nothing forced a different target. The mechanism is now: allow the write, snapshot, restore before grading, record the deviation. — **policy candidate** (a refusal that does not state the allowed set and force a new target is a retry loop; prefer allow + restore + record).
- [pitfall] `docs/DESIGN.md:325` (§10.3, "the exit status is not evidence") — run-authored code runs inside the gate process, and `atexit.register(lambda: os._exit(0))` made **both** pytest runs exit 0 with no summary, turning a false success into a claimed true one; green now needs a JUnit report at a private `mkdtemp` path outside the repo, with the expected test id and a per-run random canary node id. `docs/STATUS.md:550` (§8f) still lists the residual: adversarial code can forge the gate's own evidence (tamper-evident, not prevented). — **policy candidate** (never accept an exit code as evidence; require an artefact the subject cannot write, and a canary it never saw).
- [pitfall] `.scratch/28-three-requirements/issues/fix-wave-1-independent-review.md` (finding P2-2) — a mechanism (`failure_is_test_attributed`) shipped with unit tests but is unreachable in production: excerpt shaping hands the judge at most the first three failure-marker lines, which contain no `path.py:line:` frame, so the predicate is always False; it "appears in none of the 16 recorded run trajectories". — **policy candidate** (a mechanism with unit tests and no production input is unproven; grep the real trajectories before calling it done).
- [pitfall] `.scratch/28-three-requirements/issues/fix-wave-1-independent-review.md` (finding P2-1) — the handoff claimed a fix changed behaviour (blocking an unmet criterion); the reviewer's exhaustive 56-case enumeration found **0** behaviour differences, so the accompanying test tested the helper's existence, not a decision. — **policy candidate** (a fix claim must name the observable behaviour it changes plus a test that fails before it; otherwise it is record-only and must be described as such).
- [pitfall] `.scratch/28-three-requirements/issues/fix-wave-1-independent-review.md` (findings P2-3, P2-4, P2-5) — three traceability defects from one wave: a falsy `delivered_tier` made the record report the run's terminal tier for a `contract-clear` delivery; the persisted `isolation.pytest_args` no longer matched the leaf's real invocation after the flag was added inline; and the new flag removed the one bounded repair for an import error in the independent test, "a new dead end that the handoff's claim does not mention". — **policy candidate** (recorded metadata must be captured from the actual invocation, never restated by hand; a broadening flag must be checked for the repairs it removes).
- [pitfall] `docs/STATUS.md:417` (§8d) + `.scratch/28-three-requirements/issues/verification-decomposition-forensics.md:414` (§6) — per-attempt MODEL OUTPUT was never persisted (only `claimed_delta`, `touched_files`, failure signature), so "did the model emit a no-op file, or did something revert a real fix?" could only be inferred; capturing the envelope content or hash is stated as a prerequisite for the next round. — **policy candidate** (record the bytes *and* the hash per attempt; a question that needs the original artefact cannot be answered later, and a hash alone answers "did it change").
- [pitfall] `.scratch/28-three-requirements/issues/26-pi-maxed` round 2 (`docs/STATUS.md:368` §8c consequence) — pi's "claimed" column was a regex over its final assistant message, and 10 of its 11 non-claims were *empty* truncated messages, so "missed 0" was an artefact of the instrument; the columns were not comparable and `STATUS.md` 8c had to be corrected. — **policy candidate** (before comparing two subjects on a metric, prove the metric means the same thing on both; an instrument that cannot express "no claim" reports zero misses).
- [pitfall] `docs/STATUS.md:505` (§8) — "asking a small model to write its own tests made a mature CLI WORSE (21/40 → 16/40)"; the paragraph stayed published for days until the mechanism turned out to be **our own 8192-token window** (9 of 10 tail runs ended on a length-truncated thinking block) and the finding was marked "8k-only, un-remeasured at 32k". — **policy candidate** (state the conditions with the number; a limit of your own configuration masquerades as a property of the subject).
- [pitfall] `docs/STATUS.md:614` (§8h) — the strict claim rule (only a deterministic behaviour-level anchor may carry a claim) drove false successes to 0 and claims "from 10/40 toward the handful", so a passing-but-unclaimed revision must be read as "fixed, evidence is model-written only". — **policy candidate** (a honesty rule has a measurable missed-claim cost; decide which error the consumer tolerates and label the claim basis so they can filter).

### Know-how

- [know-how] `bench/FAIL_PATTERNS.md` (FP-6) — a **same-length edit** (`is` → `==`) can reuse the previous source's cached `.pyc`, so pytest passes on broken code; fix: `PYTHONDONTWRITEBYTECODE=1` + `-B` in the check environment. — **policy candidate** (a green run can be stale; byte-compilation caching is a correctness hazard for generated edits).
- [know-how] `bench/FAIL_PATTERNS.md` (FP-1, FP-2) — the reference 4B drops `"""` on re-emission of a file seen in context (a line-1 parse error, 4/4 replicas at temp 0.2) and reports the *tests'* failed state as its own operation status, which discarded a correct fix that was present in the envelope. Both are fixed by a hard-rule prompt block with proven wording. — **policy candidate** (for a weak model, a re-emitted artefact and the operation status are both unreliable; pin both in the prompt and never parse meaning out of free status text).
- [know-how] `bench/FAIL_PATTERNS.md` (FP-3, FP-10) — a grounding validator that rejects unknown tokens also rejected `e.g`/`i.e`, the numeric literal `4.5`, and a file the **request names for creation** (`plugins/registry.py`, absent from the symbol DB), and the implement guard refused to create new files at all. — **policy candidate** (a validator that rejects the unknown will reject abbreviations, literals and things that do not exist yet; it needs explicit exemptions and a creation path).
- [know-how] `bench/FAIL_PATTERNS.md` (FP-7) — symptom-layer anchoring: the fix went to `auth/sessions.py` (where the symptom shows) six times instead of `auth/config.py` (where the wrong value lives), because the failing-test excerpt named only session-layer symbols; the fix is surfacing module-level constants plus the rule "fix where the VALUE lives, not where the symptom shows". — **policy candidate** (when handing a bug to an agent, say where the value lives, not only where the failure shows).
- [know-how] `bench/FAIL_PATTERNS.md` (FP-9) — a check ladder inherited ruff's evolving default rule set; 0.16 added DTZ007, which flagged the **correct** T-17 fix (naive datetimes by design, because the tests inject naive inputs) on every attempt, and the model chased the lint into breaking the logic; the stage is now pinned to `--select E9,F`, widened only with run evidence. — **policy candidate** (pin the toolchain and its rule set; an unpinned style rule must never gate correctness).
- [know-how] `bench/FAIL_PATTERNS.md` (the closing rules) — "a pattern enters this file only with a reproducible run reference; it leaves only with a green re-run after the fix", and composition-layer fixes belong in the shared prompt rules, not in per-task scripts. — **policy candidate** (a failure register with an entry criterion and an exit proof is what stops the same bug returning under a new name).
- [know-how] `.scratch/28-three-requirements/issues/28-three-requirements.md` (Q1 result) — what a bigger budget buys is **agency**, not authoring: T-31's four-file threading is fixed given room to iterate (49 s, 9 turns), while the whole-implementation anchors stay 0/5 both ways, and A-03/A-05 spent 238 s / 207 s in a **single turn with zero tool calls** because one thinking block ate the per-turn output budget. — **policy candidate** (a bounded-output model can burn its whole turn in thinking and never call a tool; count tool calls, not turns).
- [know-how] `docs/DESIGN.md:325` (§10.3) — a review that is about to GRANT must name the acceptance criterion **and** the behaviour/observable/value it verified; naming a changed path or a bare `line N` "is grounding, not substance", and the refusal is recorded (`review_not_grant_calibre`), while a negative/uncertain review is untouched. — **policy candidate** (an approval must carry substance, or the rule blocks thin approvals without muting review feedback).
- [know-how] `.scratch/28-three-requirements/issues/fix-wave-1-independent-review.md` (FIX 5) — the review is attributed to the **source-revision fingerprint**, so a later round cannot approve a revision that an earlier round rejected without the bytes changing. — **policy candidate** (a verdict is bound to the revision it saw; an approval of "the tree" is meaningless when the tree moves).

### Detours

- [detour] `docs/STATUS.md:163` (§3, "What was tried and did NOT help (measured, not guessed)") — injecting a knowledge pack (4/15 vs 3/15), putting importers in the write spec (10/15 vs 10/15), forcing a deterministic file-change order (**harmful**, 14/15 vs 7/15), extending the write boundary on rule evidence (1/5 vs 1/5), competitive How exploration (~5× calls and wall time for fewer fixes), and a bounded source index (**harmful**, 13/24 vs 18/24; "Source is never hidden from the model now"). The stated pattern: "structure that costs calls without adding **information** loses." — **candidate** (the policy misses the two concrete negatives: never hide source to save tokens, never impose a deterministic file order on the agent; and "a knowledge pack is not information").
- [detour] `docs/DESIGN.md:559` (§10.8a) + `docs/STATUS.md:505` (§6.1) — three claim rules were built, measured and replaced (own-test-only, independent-test-as-veto, review-precedence), with the verdict "the claim rule is settled by measurement; do not re-open it without new numbers". — **project rule** (a rule settled by measurement is closed until the measurement changes) — **policy candidate**.
- [detour] `docs/STATUS.md:163` (§3, last row) — the byte-stable context block / artefact de-duplication alone produced no measured win, and the `-31.3%` token headline "is RETRACTED"; only C1 + full source injection survived. — **policy candidate** (a token-reduction claim must be re-measured against the outcome it was supposed to buy).

### Project rules (written after being burned)

- [project rule] `.scratch/active-work.md:31` — "A flow change is not done until it has been exercised once against the REAL model… Unit tests alone have let dead paths ship repeatedly here." — **policy candidate** (the real-input exercise is part of done, and this project had to write it down because unit-green dead paths shipped more than once).
- [project rule] `.scratch/active-work.md:31` — "The test gate is the authority… Never pipe it; check the exit code", "Check the server before any measurement", "One writer per work tree. Never edit code while a measurement lane is running", "A headline that a later measurement contradicts gets retracted in the same commit that contradicts it". — the retraction rule is a **policy candidate** (the policy's `outdated` covers deleting dead facts but not same-commit retraction of a contradicted number); one-writer is **already covered by `writers`**; never-pipe and health-check are **project-specific**.
- [project rule] `.scratch/28-three-requirements/issues/28-three-requirements.md` (Discipline) — "Model-ceiling may only be recorded with the recurring failure quoted per task, and never from a `stop_reason` label alone." — **policy candidate** (a failure label is a diagnosis claim and needs its quoted evidence; `docs/STATUS.md:550` §8f is the delivered table that does it).
- [project rule] `bench/corpus/README.md` — every task "ships BROKEN": red→green verified by hand before entry, the repo restored to its exact broken bytes afterwards (SHA-256 checked), no solution leakage, and `request.md` "written as a real user would write it: symptom first, hunches allowed, no file paths or symbol names given away". — **policy candidate** (a benchmark fixture's red-before/green-after state must be verified and byte-restored, and the request must not name the fix).
- [project rule] `docs/DESIGN.md:325` (§10.3) — one claim gate enforced by a structural AST test, per-criterion and request-level artefact coverage, ledger rows in both directions, `UNTOUCHED` is not a write guard, and an unobservable regression suite is "NEVER `no regression`". — **policy candidate** (a claim path must be structurally singular, and "could not be observed" must never be recorded as a pass).

## Top 5 by value

1. **The exit status / green suite is not evidence — and the gate's own environment is part of the test.** `docs/DESIGN.md:325` shows a lie manufactured with `atexit` + `os._exit(0)`, and `.scratch/incident-20260930/README.md` shows a stray root `conftest.py` that would have reported green for everyone running the suite. One rule ("require an artefact the subject cannot write, plus a canary, and check the gate's own environment") prevents the entire class.
2. **A verification authored by the same generator that wrote the code is not corroboration.** `docs/DESIGN.md:559` (§10.8a) documents the shared-misreading false success, and `.scratch/28-three-requirements/issues/requirement-2-ablation.md` measures the price of each stage: own test Δactual −1.33 [−5.67, +3.00] at 7× tokens, review alone +18 claims and +3.33 false successes (p = 0.031), IV false-blocks 57 of 92 grader-passing runs. This is the strongest quantitative argument the general policy could carry.
3. **Verification written by the model often asserts the bug.** `with pytest.raises(IndexError)` for the crash the request asks to remove (`.scratch/26-pi-maxed/…`, 8 of 11 missed wins): "assert the desired end state, never the reported symptom", and check the test is red on the *fix*.
4. **A guard that refuses and does not redirect is a retry loop.** `.scratch/26-pi-maxed/…` (T-01, six identical refused attempts, task lost that pi fixed in one turn) — allow the write, snapshot and restore it before grading, and always tell the agent what it *may* touch. `docs/FLOW.md` §5 already states the replacement rule.
5. **What you did not record cannot be diagnosed — record the artefact bytes and hash per attempt, and bind every verdict to a revision fingerprint.** `docs/STATUS.md:417` (§8d) and `…/verification-decomposition-forensics.md:414` (§6.2) both name the missing per-attempt model output as the reason a forensics question stayed unanswerable; the same project's review findings (P2-3/P2-5) show hand-restated metadata drifting from the real invocation.
