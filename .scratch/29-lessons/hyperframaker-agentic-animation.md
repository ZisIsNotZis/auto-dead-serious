# Lessons: `hyperframaker` and `agentic-animation`

Coverage note (limitation): I read the contract, then `AGENTS.md`/`README.md`/`CONTEXT.md` and
`docs/` for both projects, `hyperframaker`'s agent guide and status doc, `agentic-animation`'s
`.agents/knowledge/`, its local `.agents/skills/*/SKILL.md` (the vendored Remotion/Anthropic skills
are third-party and were not judged), and 15 of the 44 tickets in `agentic-animation/docs/tickets/`.
The remaining ~29 tickets and `WORLD_PUPPET_MOTOR.md`, `WORLD_PLUGIN_CONTRACT.md`, `SHOWCASES.md`,
`ART_*` (except M2) were not read; findings below are what the read files evidence, not a full
inventory. Nothing in either project was written to. Where I concluded something the file does not
literally say, it is marked as inference.

## hyperframaker

- [doc method] `docs/design.md:13` - "Imported external files are copied into their new node directory" contradicts `README.md:99` "Imported paths remain references; they are not copied"; `server/index.mjs` `/api/import` does `copyFileSync` into the node directory, so the design doc is the stale one - policy candidate: `references_resolve` only makes paths/keys/commands mechanically checkable, and nothing catches a behavioural sentence that contradicts the code.
- [doc method] `README.md:99` - "A generated node lives in `.hypermaker/nodes/<id>/`" names a path that does not exist: the workdir holds `2/ 4/ 5/ 6/`, `server/index.mjs` writes `join(workdir, String(id))`, and `docs/design.md:11` says `<workdir>/<id>/` - already covered by `change.docs.references_resolve`.
- [doc method] `docs/design.md:13` - "No manifest, recursive import discovery, versioning, copy-on-link, or simultaneous workspaces" contradicts `README.md:46` ("recursively discover their manifest-backed parents"), the `Manifest` row at `README.md:96`, and `docs/impl.md:11` ("No old-manifest compatibility layer") - policy candidate under `doctrine.main_point`: the product source of truth and the user-facing doc hold two versions of one fact.
- [doc method] `docs/design.md:17-19` and `docs/impl.md:23-25` - the same paragraph appears twice in each file with different clause sets ("Dragging continues for the complete pointer gesture even when pointer leaves the card title bar" only in one copy; "Card raising must not move a card during pointerdown on an interactive control" only in the other) - a botched edit that added the new text without deleting the old, so one fact now has two homes that will drift - already covered by `doctrine.main_point`.
- [doc method] `AGENTS.md` (last line, under "# Hypermaker agent guide") - "For agent-document writing conventions, see `.agents/skills/writing-for-agents/SKILL.md`"; that skill does not exist, `.agents/skills/` contains only symlinks to the vendored `hyperframes-*` and `remotion-*` skills - already covered by `change.docs.references_resolve`.
- [project rule] `AGENTS.md` "# Hypermaker agent guide" - "Generated nodes always have `AGENTS.md`; leave it empty when no reusable memory matters", and `docs/design.md:23` "Agent runs with repository root cwd so `.agents` loads, writes only current node directory" - the project settled on a per-artifact empty-by-default memory file plus a single writable directory - policy candidate: the general policy has no rule for artefacts that carry their own handoff file for the next agent turn.
- [doc method] `README.md` (parts of the root) - the project carries four spellings of one name: directory `hyperframaker`, `package.json` `"name": "hypermaker"`, `README.md:25` "Hypermaker started around HyperFrames" / the repo clone URL, and `docs/design.md:1` "HyperMaker" - already covered by `resources.efficiency.one_name_one_thing`.
- [know-how] `README.md:79` and `test/e2e.test.mjs:1-12` - "Browser tests need a Playwright-compatible Chromium. If your environment blocks Chromium's sandbox, run them in a normal desktop/container browser environment"; the e2e test fakes the agent by writing a `codex` shim script into a temp dir and injecting `CODEX_BIN` - project-specific, but the shim-injection trick is a reusable way to test an agent-harness end to end without a live model.

## agentic-animation

- [doc method] `AGENTS.md:36-38` - "Put temporary task lists in `.scratch/` only while working, then promote durable conclusions to the owning document and remove the scratch note"; eight task lists from 2026-08-26 to 2026-09-28 are still sitting in `.scratch/`, and `docs/tickets/M2-DOC-READINESS.md:46-49` records that the documentation audit found "conflicting next steps/gates" in scratch - the rule was written and then not followed, and the scratch notes became a second state ledger - policy candidate.
- [doc method] `docs/INDEX.md:38` + `docs/tickets/` (44 files) - "Tickets own process history/provenance" placed the whole work record *inside* the documentation SSOT, while `AGENTS.md:36-38` says durable conclusions are promoted out of `.scratch/` into the owning document - policy candidate: the general policy's `docs.ssot_boundary` puts tickets/logs/evidence outside the SSOT, and this project deliberately reversed that, so the policy needs to say what a work record inside the docs is allowed to be.
- [project rule] `docs/INDEX.md:33-43` - an explicit precedence chain: "For public behavior, the DSL and schemas win. Architecture defines module ownership; pipeline defines operating order; decisions define durable choices; status routes current milestone state; each milestone document owns its evidence, acceptance and next actions... If implementation or an episode contradicts a contract, update the owning document, then change code or content." - policy candidate: this is a per-project precedence order the general policy only states abstractly.
- [doc method] `docs/tickets/M2-DOC-READINESS.md:137-165` - the independent audit's verdict "NOT PASS - integrated SSOT reconciliation remains blocked": `docs/STATUS.md:81` called the shipped orientation/fabric work "Slice 3" against a motor owner that has Slice 3 pending, and `docs/STATUS.md:77` named `packages/core/src/motor/figureGeometry.ts` as the geometry SSOT although `test -e` returned 1 and the owner names `motor/skeleton.ts` - already covered by `change.docs.doc_checklist` (One home, Resolvable), with a strong reproduction.
- [doc method] `docs/tickets/M2-STATUS-REPAIR.md:5-9, 44-51` - the repair's own interpretation: "STATUS is a current milestone router, not a chronological evidence log"; its removed baseline/runtime/Visual-QA history is preserved verbatim in a ticket instead of being deleted - a working recipe for de-rotting a status file while keeping the evidence - policy candidate.
- [doc method] `README.md:104` - links `[CLAUDE.md](CLAUDE.md)` as "agent operating guide"; the repository has `AGENTS.md` and a `.claude -> .agents` symlink, and no `CLAUDE.md` - already covered by `change.docs.references_resolve`.
- [doc method] `README.md:121-123` - "The latest recorded checks are summarized in `docs/STATUS.md`: typecheck, 112 passing tests with 7 skips" while `docs/STATUS.md` no longer holds counts at all and the tickets record 184/7, 216, then 250 - a status figure with no producer that nobody updates - already covered by `change.docs.citation_not_value`.
- [doc method] `README.md:12` vs `docs/STATUS.md:14-24` - README says "Status: **closed (milestone, 2026-09-29)**... Remaining ideas are deferred as backlog", STATUS says the M0-M8 art roadmap "remains active" with "**M2 is incomplete**" and 44 open M2 tickets - two live files disagree about whether the project is finished - policy candidate under `doctrine.main_point`.
- [pitfall] `docs/tickets/M2-SUCCESSIVE-CLAIM-CONTINUITY.md:35` - "Saved native run 7daa8591 actual log confirms timeout 2400000ms after failed actual native 24.045475643269608px proof, not success; prior checkpoint ticket omitted closure narrative" - a 40-minute timeout was carried forward as a completed checkpoint until the raw log was read - policy candidate under `proof.execution.surprise_is_a_signal`: read the run record, not the previous summary of it.
- [pitfall] `docs/tickets/M2-SUCCESSIVE-CLAIM-CONTINUITY.md:39` - "Original small .6-scale fixture concealed full .92-scale native geometry failure; added nativeDraftArtworkFixture regression with duplicated separate bone tracks red at 27" - a test fixture at the wrong scale hid a production defect, and the first repair attempt ("seed + full successor envelope double-counted onset velocity") was only diagnosable after the fixture was made production-scale - already partly covered by `proof.execution.only_authorized` ("use checks capable of catching them"); the fixture-fidelity angle is not.
- [pitfall] `docs/tickets/M2-STATUS-REPAIR.md:95` - "the Remotion webpack persistent cache served stale component code after source changes (silently rendering outdated faces/framing); bundling now runs with `enableCaching: false`" - the rendered evidence was silently of an older revision - policy candidate: a build cache that can serve stale code invalidates visual evidence, and nothing in the policy treats cache state as part of the revision a proof is bound to.
- [pitfall] `docs/tickets/M2-LIVE-INTEGRATION.md:95-101` - "settled requires BOTH feet !swing, but nonzero walk phase schedules one swing, so phase cannot terminate and 12design-px gait reserve keeps body compressed" - a circular termination condition inside a physics state machine, found only by an exact whole-body reproduction after a 40-minute budget expired - know-how: per-joint checks passed while the whole-body invariant was unsatisfiable - policy candidate.
- [detour] `docs/tickets/M2-LIVE-INTEGRATION.md:71-72` - "Earlier binary retries unnecessarily restricted feasible travel to 210px/s; finer whole-state proposals preserve strict thresholds and enable contact readiness" - a bisection/retry strategy was abandoned because narrowing feasibility hid the real reach problem - project-specific to motion planning, but the shape (a repair that reduces the search space instead of fixing the proposal) is general - policy candidate.
- [detour] `docs/tickets/M2-CONTACT-MODEL.md:47-49` - "Initial exponential candidate caused 32.88/37.90px first-frame recovery jumps in the actual draft challenge; rejected and replaced, not thresholds weakened" - already covered by `resources.efficiency.fix_the_root`, though the explicit "not thresholds weakened" phrasing is a project rule of its own.
- [project rule] `docs/tickets/M2-CONTACT-MODEL.md:126-130`, `M2-EXPRESSION-CONTINUITY.md:10-13`, `M2-LIVE-INTEGRATION.md:42-44` - the same prohibition is restated in every contract: "never weaken thresholds", "no speed/threshold reduction", "Reject four-string exclusion patch", "Do not clamp measured joints or relax thresholds", "suppressing warnings" is not a repair - the general policy's nearest rule is `fix_the_root`; the "the check is not the defect" rule is not stated explicitly - policy candidate.
- [pitfall] `docs/tickets/M2-EXPRESSION-CONTINUITY.md:54-56` - "Copied physical helper initially rewrote historical proof with IDENTICAL bytes; verified ae6d10eb... agrees with original handoff inventory, no artifact-byte change. Helper corrected to write only this bundle" - a copied packaging helper silently republished into a frozen archive; it happened to be byte-identical, which is why it was caught rather than trusted - know-how: a frozen bundle must be write-protected against the helper that regenerates it (the project's later fix: `package.py` "excludes inventory self-inclusion and independently verifies source/audio/artifact/links", `M2-EXPRESSION-CONTINUITY.md:75-80`).
- [pitfall] `docs/tickets/M2-FINAL-HANDOFF-INDEPENDENT-REVIEW.md:36-39` - "artifact-hashes.json inventories itself with expected fd7d7303... but actual is 5021d9... This is a self-reference inventory construction error... Writer must omit the self entry and bind the inventory externally" - a hash inventory cannot contain its own hash; the false entry looked like tampering - policy candidate under `proof.execution.bind_to_revision`.
- [pitfall] `docs/tickets/M2-EXPRESSION-CONTINUITY.md:78-80` - "Package first link pass found inventory not created yet; corrected construction ordering" and `M2-DOC-READINESS.md:125-127` "A guessed nonexistent `test_lin_anchor.py` command failed; actual discovered test files then passed" - two forms of the same failure: a command or path invented from memory instead of discovered - already covered by `change.docs.references_resolve`.
- [pitfall] `docs/tickets/M2-CONTACT-CONTINUITY-REVIEW.md:76-78` - "An initial malformed profile challenge omitted evaluator orientation tracks while rotating motor geometry; its warning result was rejected as invalid, then corrected and rerun across all eight orientations. It is not a finding" - a broken harness produced a plausible pass and was nearly booked as evidence - already covered by `proof.execution.surprise_is_a_signal`.
- [know-how] `docs/tickets/M2-FINAL-HANDOFF-INDEPENDENT-REVIEW.md:63-80` - "Read-only tsx evaluation reproduces all 157 warning objects exactly... **83 entries** are abrupt onset/binary peak/phase-reset boundaries. The other 74 entries are fast sampled onset/recovery rates: real FK motion, but a threshold exceedance alone does not prove a discontinuity" - a numeric detector split into 83 real defects and 74 threshold noise, and acceptance required consecutive frame inspection, not the detector - policy candidate: a metric that passes or fails is not the acceptance when the artefact is perceptual.
- [know-how] `docs/tickets/M2-FINAL-HANDOFF-INDEPENDENT-REVIEW.md:56-62` - "H links C/evidence/matched-comparisons.png, which shows historical candidate pickup/transfer/rest (e.g. upright cup at 44/96), not the current wrist-rotated socket/support candidate... Do not use it as final matched contact proof" - a reused comparison image silently became a claim about a newer candidate; the fix is labelling it historical or hashing a matched beat - policy candidate.
- [know-how] `docs/tickets/M2-CONTACT-MODEL.md:135-140` - "profile at x543.078, pitch85/crouch1 leaves hand y608.690 vs socket636 (27.31px deficit). Alignment cannot cure vertical reach. Fixed 90 design-px crouch is not native leg capacity. Use half the shorter native hip-to-foot chain length as a bounded shared motor/renderer crouch drop" - the root cause was a constant standing in for a physical capacity, and it was only visible because the diagnostic printed the actual deficit - project-specific.
- [pitfall] `docs/tickets/M2-DOC-READINESS.md:41-42` - "A timed-out reviewer resumed, identifying CSS origin and dropped crouch defects"; and `M2-EXPRESSION-CONTINUITY.md:146` "One targeted aggregate60sec command timed out and was killed; no leaked jobs" - timeouts were routine in both directions (reviewer and worker) and the review's value survived the timeout only because the run was resumable - already covered by `proof.process.bounded` and `proof.process.context_pressure`.
- [pitfall] `docs/ART_CHARACTER_M2.md:168-179` - step 2 says inspect `/tmp/agentic-animation-art-m2-parts-20261008/` and step 3 is a full reconstruction recipe "If `/tmp` is missing, reconstruct a NEW workspace from immutable checkpoint `draft-library`, `episodes`, `native-sprites`, helpers and frozen M0 audio... Preserve episode/library relative layout and regenerate manifests because old paths can be absolute" - the iteration workspace lived in disposable storage for weeks and the recovery path had to be written down - policy candidate: `resources.environment.artifacts_home` says durable artefacts belong in the project, and this project instead keeps evidence under `~/.local/share/agentic-animation/art-baselines/` with `/tmp` for work.
- [pitfall] `docs/ART_CHARACTER_M2.md:198` and `docs/tickets/M2-FINAL-HANDOFF-INDEPENDENT-REVIEW.md:196-198` - "Final source is dirty; use the seam-repair ticket's hash-bound archive, not old checkpoint media" / "pre-existing .gitmodules/vendor gitlinks stay staged... No NEW staged files; an empty-index assertion is false" - a month of deliberately uncommitted work means HEAD cannot identify what was rendered, so every package has to carry its own SHA256 source inventory, and "no staged files" is not assertable in this repository - policy candidate for `proof.execution.bind_to_revision`, which assumes a commit or worktree hash is available.

State exactly what was and was not verified"; `AGENTS.md:28-29` "A failed command or partial result is not completion"; `.agents/knowledge/ssot-and-evidence.md:9-10` "Passing tests does not prove visual or audio quality; actual artifact inspection does" - already covered by `proof.review.three_kinds` and `proof.review.unverified_is_not_pass`, stated more sharply than the policy does.

Require two iterations for changed visual behavior" - a project rule that a contact-sheet filename is not evidence, and a fixed two-pass minimum - policy candidate next to `attention.communication.multimodal_review`, which states the need for multimodal checking but no minimum.
- [know-how] `docs/DECISIONS.md:53-59` - "Do not infer this machine's hardware, installed services, voices or performance from stack choices. Inspect local configuration before execution... - [pitfall] `docs/SCHEMAS.md:91-113` with `docs/tickets/M2-SVG-VALIDATION-REPAIR.md:9-13` - an external-CSS injection blocker in figure-artwork validation; the repair chose "enforce a small non-executable SVG element/attribute grammar" over "blacklist CSS spellings (fragile against escapes/entities)" - a real security-shaped defect in generated asset data, and the accepted fix is an allowlist that fails asset loading rather than falling back to an old look - policy candidate: untrusted *generated* asset content is an input the policy's `intent.untrusted_input` covers for retrieved content only.
- [project rule] `.agents/skills/self-improve/SKILL.md:19-35` - "Execute only within the current authorization. Local inspection, scoped edits, tests, and `/tmp` artifacts are safe defaults. Destructive cleanup, broad contract changes, production TTS/render, commits, pushes, and external communication require explicit permission unless the user authorized an unattended run" and "When it is unavailable, stop at the authorization boundary rather than treating absence as approval" - already covered by `intent.risk.covered_once` / `attention.phases`, but this is the clearest short statement of the safe-default boundary seen in either project.
- [doc method] `AGENTS.md:22-23` - "Keep docs and skills concise, docs-first, and single-source; ordinary Markdown stays below 200 lines" (enforced: `M2-DOC-READINESS.md:104-107`, "motor is 199") - inference: the cap pushed the M2 milestone's content into 44 tickets, and the owner doc compensates with very long single-line paragraphs (e.g. `docs/ART_CHARACTER_M2.md:157`), which is a length rule trading against readability - policy candidate.
- [pitfall] `docs/tickets/M2-DOC-READINESS.md:43-45` - "Supplemental acting clip showed expression carry-over and default two-hand point; it is not a clean one-hand acceptance sample. Latest local test log records 184/7" and `M2-DOC-READINESS.md:15-17` "user said 'seems much better, go on'. This accepts identity derivation, not production rig readiness" - the project's rule is that a supply of hand-made clips can accumulate without ever containing the one sample the acceptance needs - policy candidate under `proof.review.falsify`.

## Top 5 by value

1. `docs/tickets/M2-DOC-READINESS.md:137-165` + `M2-STATUS-REPAIR.md:5-9` - a live status document accumulated process history until two of its statements were false (a slice label and a source path) and an independent reviewer had to reconstruct which facts were current; the working fix - status routes to owners, history is preserved verbatim in a ticket, and a link/heading/line-count check runs over the docs - is the concrete version of the policy's abstract One-home and Resolvable rules.
2. `docs/ART_CHARACTER_M2.md:198` + `M2-FINAL-HANDOFF-INDEPENDENT-REVIEW.md:196-198` - an intentionally dirty tree for a month makes HEAD unable to identify a rendered output and makes "no staged files" unassertable, so each package must carry per-file SHA256 inventories and an external binding; `bind_to_revision` assumes exactly the thing this repository could not provide.
3. `docs/tickets/M2-SUCCESSIVE-CLAIM-CONTINUITY.md:35` + `M2-EXPRESSION-CONTINUITY.md:54-56` - a timed-out run was carried forward as a completed checkpoint, and a copied helper nearly rewrote a frozen archive; both were caught only by reading the raw log and the bytes, which is what `surprise_is_a_signal` should require explicitly.
4. `docs/tickets/M2-STATUS-REPAIR.md:95` - a persistent build cache served stale component code and the rendered evidence was silently of an older revision; proof must include the state that can invalidate it, not only the source hash.
5. `AGENTS.md:36-38` versus the eight stale `.scratch/` task lists and 44 tickets inside `docs/tickets/` - the project's own rule (scratch notes are temporary, conclusions are promoted into the owning document) is already violated, and the work record ended up inside the SSOT, which is the opposite of the policy's `ssot_boundary`.
