# Durable and agent-facing writing

Use for durable documentation or agent-policy creation/change/review. Apply these rules to this package too; do not invent documentation for unchanged behavior.

- **Source and home:** trace product decisions to explicit user decisions or accepted requirements; an `approved` label is not evidence. Keep one authoritative home and link to it. Mark unresolved consequential interpretations provisional and update changed contracts before or with implementation. Retain raw sources only when provenance warrants safe storage; they are not automatically operational truth.
- **Placement:** put product decisions in target-project documentation, transient contracts/evidence/handoffs in its work records, shared agent boundaries in the owning `AGENTS.md`, and event-specific methods in its companions. Use an existing project convention for verified environment facts when needed; policy must not require a workspace-specific document. Resolve policy references from their owner and project artifacts from the target project. Create reusable skills/automation only for demonstrated need.
- **Executable rules:** identify subject, event/trigger, action, checkable output, and any exception. Separate hard boundaries from conditional methods. Remove lines that change no decision or safeguard; replace duplicates rather than append philosophy or vague qualifiers. Use specific names and scenario rereads to expose ambiguous boundaries. Size diagnoses load; it is not permission to remove safety or hide bulk in mandatory reads.
- **Policy proof:** the worker records durable rationale/options and core/package size before and after, rereads scoped artifacts, audits references/routing, and runs scoped `git diff --check`. For authority, safety, role, context, routing, or compatibility changes, also check concrete affected scenarios. Obtain fresh independent acceptance under the execution review loop; self-checks do not substitute. Bind checks to final policy hashes/revision and rerun invalidated checks. Distinguish documentation checks from untested runtime behavior/configuration.
- **Compatibility:** update the owning index when references change; missing optional companions are not grounds to invent files. Historical records need no rewrite if their meaning remains recoverable. Rules must work without a particular model, platform, optional skill, tracker, or assumed tool guarantee.
